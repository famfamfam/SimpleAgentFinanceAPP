# Разработка

[English](DEVELOPMENT.en.md) · [На главную](README.md)

Нужны Go версии из `go.mod`, Node.js 24, Docker и Compose v2. Команды ниже
выполняются из корня проекта. Для сервера и конфигурации см. [DEPLOYMENT.md](DEPLOYMENT.md).

## Клиент и сервер

```sh
npm ci
npm run build
```

Vite собирает React в `backend/react-web/dist/`; Go встраивает результат в бинарник.
Docker выполняет сборку клиента автоматически. Без dist сервер может запускаться
и отдавать API и общие модули, но для HTML и Service Worker отвечает 503.

Для разработки запустите тестовый API на `http://127.0.0.1:18080`, затем:

```sh
npm run dev
```

Откройте адрес, выведенный Vite. Он проксирует API и общие браузерные модули на
Go-сервер; другой адрес API задаётся через `VITE_API_TARGET`. В `frontend/src/`
находятся React-компоненты, в `backend/web/` — единственные экземпляры модели,
IndexedDB, sync и Service Worker, используемые и React, и сервером.

## Проверки

```sh
npm run format:check
npm test
npm run build
go vet ./...
go test ./...
npx playwright install chromium webkit
npm run test:e2e
```

`npm run format` форматирует React-код. Браузерным тестам нужен отдельный тестовый
API на `http://localhost:18080`, либо адрес из `TEST_URL`. Пароль регистрации
тестового API задаётся через `TEST_REGISTRATION_PASSWORD`. Не запускайте эти тесты
на рабочей установке.

Без `TEST_DATABASE_URL` и `TEST_REDIS_URL` часть Go-интеграционных тестов
пропускается. PostgreSQL-тесты создают и удаляют отдельную схему; Redis-тесты
используют базу 15 и очищают тестовые ключи. Используйте изолированные сервисы,
не production. `deploy/compose.test.yaml` открывает тестовые порты 15432 и 16379
на loopback при подключении к отдельному Compose-проекту. Для гонок используйте
`go test -race ./...` в окружении с поддержкой race detector.

## Данные и совместимость

IndexedDB хранит подтверждённый снимок и очередь команд, применяемую поверх него.
Команды нельзя переписывать под прежними UUID: сервер использует их содержимое для
безопасного повтора. Невалидные или конфликтующие изменения остаются на устройстве.
Старые данные без валюты означают RUB; итоги разных валют не объединяются.

Сервер хранит книгу в PostgreSQL JSONB и проверяет членство и версии под блокировкой.
Новые клиенты сообщают версию данных 4; несовместимый клиент получает 426, не
теряя очередь. JSON-копии v4 содержат данные, очередь и переписку; старые RUB-копии
поддерживаются. Изменения API и форматов проверяйте также на старых очередях и копиях.
Не изменяйте уже применённые SQL-миграции.

Данные для браузерных и резервных тестов должны быть вымышленными. Проверка WebKit
не заменяет тестирование Safari на реальном iPhone.
